# Bezpieczeństwo danych uwierzytelniających w repozytorium

W publicznym repozytorium nie wolno umieszczać haseł ani kluczy dostępu (API keys, tokenów), ponieważ są one natychmiast indeksowane przez automatyczne boty skanujące internet w poszukiwaniu danych uwierzytelniających, co prowadzi do przejęcia infrastruktury lub generowania gigantycznych kosztów. Zwykłe usunięcie pliku w nowym commicie nie rozwiązuje problemu, ponieważ system Git zachowuje pełną historię każdej zmiany i każdy może cofnąć się do wcześniejszego zatwierdzenia, by odczytać usunięty wpis. Aby trwale usunąć wyciek, konieczne jest nadpisanie historii repozytorium (np. za pomocą narzędzi takich jak `git-filter-repo` lub BFG Repo-Cleaner) oraz natychmiastowe unieważnienie (rotacja) ujawnionego klucza u dostawcy usługi.
